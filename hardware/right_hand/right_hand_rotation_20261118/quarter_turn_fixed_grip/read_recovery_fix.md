# 빈손 준비 중 통신 중단과 읽기 복구 수정

실행 근거: `quarter_fixed_grip_trial_20261118_044845_945809/result.json`.

큐브 배치 전 `quarter_empty_move` 약30.06초,397목표 진행 후 주소64의 전체 상태 읽기에서 `comm=-3002`가 연속 두 번 발생했다. 두 번 모두 ID1 다음 ID2 응답부터 완성하지 못했다. 깨진 패킷과 부분 시간 초과를 구분할 원시 수신 바이트는 저장되지 않아 USB·케이블·모터 자체 중 무엇이 원인인지는 확정하지 않는다. 큐브/추종/전류 제한으로 중단된 기록은 아니다. 직전 정상 표본까지 최대89mA·최소4.9V·최대추종0.01534rad·최대25도였으며 토크OFF와 설정복구는 확인됐다.

수정은 새 파지 실행기의 `PoseBus.snapshot`에만 적용했다. 첫 불완전 읽기 뒤 수신 버퍼를 비워 조용해진 것을 확인하고 다시 읽었으나, 두 번째 불완전 읽기는 공유200ms 기한이 남아 있어도 즉시 종료되던 분기를 수정했다. 기존 읽기 복구 정책의 최대 두 재요청과10초당3회 한도, 공유200ms 기한 안에서만 다시 읽는다. 오류가 반복되면 정상 연속 횟수를0으로 되돌리고 새 전체16개 상태가 연속 두 번 완성되어야 반환한다. 모터 장치 오류,세 번째 불완전 읽기,재시도율 초과,기한 초과는 계속 중단한다. 부분 상태로 목표를 진행하거나 위치/설정 쓰기를 재전송하지 않는다.

새 검사4개는 두 번 불완전 읽기 뒤 두 번 새 전체 상태 확인,세 번 실패 중단,장치 오류 즉시 중단,10초당3회 제한이다. 전체36개 소프트웨어 검사와 두 실행기의 장치 없는 시작 검사를 통과했다. 확정 파지와 회전 후보,기존170개 결합 파일은 보존했다. 보조자가 모터를 실행하거나 연결 상태를 새로 변경하지 않았다. 같은 `leap_quarter_to_fixed_grip.cmd`를 큐브 없이 다시 시작한다.

이 수정은 로그의 중단 분기와 복구 동작에 대한 소프트웨어 수정이다. 물리 통신의 불완전 패킷 발생 원인이나 새 파지 전환 성공을 실물에서 해결했다고 표현하지 않는다. 새 실행 결과로 확인한다.
