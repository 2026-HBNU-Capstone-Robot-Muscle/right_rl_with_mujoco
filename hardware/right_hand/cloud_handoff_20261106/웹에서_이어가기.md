# 개인 GitHub 저장소로 먼저 옮겨 웹에서 이어가기

2026-11-06 기준. 사용자는 VS Code Codex에서 하던 대화와 프로젝트를 웹과 다른 PC에서도 이어가려 한다. GitHub 계정은 이미 있다. 먼저 개인 계정의 비공개 저장소에 올리고, 팀 또는 프로젝트 쪽으로의 이전은 나중에 진행한다. 업로드 자체를 미루는 것으로 해석했던 앞선 안내는 정정한다.

## 지금 준비한 것

- `CLOUD_START_PROMPT.md`: 새 대화에 붙여 넣거나 첨부할 현재 작업 인계문.
- `last_robot_run_summary.json`: 가장 최근 로봇 실행의 종료 상태. 사진 검토 완료나 회전 성공을 뜻하지 않는다.
- `inspection.json`: 로컬 프로젝트 크기와 저장소 유무를 조사한 결과. 실행 환경과 캐시 등을 제외해도 약 38.7GB이며 현재 Git 저장소는 발견되지 않았다.
- `codex_web_context_20261106.zip`: 위 인계문, 이 안내문과 최근 실행 요약의 작은 묶음. 코드와 영상 전체는 포함하지 않는다.

2026-11-07에 코드와 모델을 선별하여 `star1209042/xlerobot` 비공개 저장소에 실제 업로드했고 원격 커밋을 확인했다. 클라우드 환경은 아직 만들었다고 확인되지 않았다. 기존 대화 원문 전체가 자동으로 웹에 동기화된 것은 아니다.

## 문맥 전달과 코드 이전

웹의 새 대화에서 `CLOUD_START_PROMPT.md` 내용을 붙여 넣으면 목표와 최근 상태를 설명하는 데 사용할 수 있다. 첨부가 가능한 화면이라면 파일로 첨부해도 된다. 파일에 없는 소스 코드나 사진은 웹 작업이 읽었다고 가정하지 않는다.

현재 진행 상황을 다른 화면에서 설명하고 계획을 이어받는 것과, 원래 코드 및 시뮬레이션을 실제로 실행하는 것은 구분한다. 원래 VS Code 대화 기록 전체를 이 문서가 대신 보존하는 것은 아니다.

## 지금 코드 실행까지 옮기는 순서

1. 원본 로컬 폴더를 보존하고, 현재 필요한 코드와 모델 및 근거 자료만 별도 폴더로 정리한다. 계정 인증 파일, 로컬 세션, 실행 환경, 대량의 원시 영상은 업로드 대상에서 제외한다.
2. 완료: `https://github.com/star1209042/xlerobot.git`가 비공개 빈 저장소임을 확인하고 `main` 및 인계 브랜치로 업로드했다. `codex_web_context_20261106.zip`은 문맥 인계용이고 `upload_repo`가 실제 Git 저장소다. 이제 `cloud/SETUP.md`에 따라 Codex 웹에 저장소를 연결한다.
3. Codex의 클라우드 환경 만들기에서 해당 저장소를 연결한다. 의존성 설치와 파일 접근을 확인한 뒤 환경을 게시한다.
4. VS Code에서 기존 대화를 연 상태로 입력창 아래 클라우드 아이콘에서 환경을 고르고 다음 요청을 보낸다. 공식 안내상 새 클라우드 대화에 기존 대화 맥락, 계획과 로컬 소스 변경을 넘기는 방식이다. 사용 중인 확장에서 이 선택 항목이 보이는지 실제 화면에서 확인한다.
5. 새 클라우드 작업이 웹에서 열리고 필요한 코드 및 모델을 읽을 수 있는지 확인한 뒤 다른 PC에서 이어간다.

로봇 USB와 웹캠은 원래 PC의 장치다. 이 저장소 이전만으로 클라우드에 연결되지는 않는다. 당분간 클라우드는 저장된 자료 분석과 오프라인 시뮬레이션에 사용하고 실물 실행은 원래 PC에서 구분한다.

## 나중에 팀 쪽으로 옮기기

팀/조직 계정으로 저장소 소유권을 이전할 수 있다. 현재 저장소 관리 권한과 받는 조직의 저장소 생성 권한이 필요하며, 받는 쪽에 같은 이름의 저장소가 있으면 안 된다. 커밋과 이슈 및 PR도 이전 대상이다. 이미 팀 저장소가 따로 있다면 두 저장소가 자동으로 합쳐지는 것은 아니므로 기존 팀 저장소에 코드를 합치는 작업으로 진행한다.
