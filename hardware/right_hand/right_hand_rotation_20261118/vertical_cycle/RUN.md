# 새 세로 이송 자세에서 세로 회전까지

최신 뒤집기 수정: 준비 이송은 유지하고, 뒤집기에서는 엄지 내림/후퇴를 먼저 끝낸 뒤 확인 SPACE로 검지·중지 뿌리 ID8/12를 세운다. 두 뿌리는 그전까지2014/2043틱에 유지된다. 끝 자세는 같고 새 순서의 실물 효과는 확인 전이다.
실행파일: 루트의 **`leap_grip_to_vertical.cmd`**.

최신 실행파일은 **G파지부터** 시작한다. 전과 같은 파지 위치에 큐브를 준비하고 손을 뗀 뒤 SPACE로 시작한다. 파지 확인 안내에서 SPACE를 누르면 검지·중지를 먼저 기록한 준비 모양으로 옮긴다. 그동안 엄지·약지는 G 목표를 유지한다. 두 손가락이 비켰는지 확인하고 SPACE를 누르면 엄지로 밀면서 약지가 함께 비킨다. 검지·중지는 이동안 목표를 유지한다. 이렇게 기존 동시16관절 이송을 순서로 나눴고, 도착할 최종 이송 목표16개 값은 그대로다.

이후 **새 세로 이송 자리 확인 SPACE → 검지·중지 목표를 유지하며 엄지·약지가 받기 → 지지 확인 SPACE → 검지·중지를 기존 세로 시작 자세로 옮기기 → 큐브 자리/지지 확인 SPACE → 기존 세로 회전 → 끝 자세 유지** 순서다. 움직이는 중 SPACE/Q/Esc는 중단/OFF다. 끝 자세에서는 큐브를 받친 뒤 SPACE로 종료한다. 이 파일에 현재 확정 G로의 복귀는 아직 포함하지 않았다. 세로 끝은 가로 복귀 시작과 다르므로 실제 상태를 확인한 후 별도 연결한다.

새 기준은 `receiving_waypoint_readonly_20261118_104640_893294/result.json`과 `current_pose.png`다. 사용자 설명은 세로용 큐브 이송 자세다. 읽기 도구의 stage 인자를 가로용 이름으로 잘못 전달했으므로 원본은 보존하고 `taught_reference_104640.json`에서 올바른 세로 의미를 명시했다. 각도나 사진의 내용이 바뀐 것은 아니다.

16개 모두 토크ON/오류0,두 번 위치차이 최대1틱,목표와 위치 차이는 최대6틱이었다. 모터 쓰기/토크 변경은0회다. 자세 목표는 실제 유지 중 읽은 다음 값 그대로이며 임의 클립과 새 관절 범위 확대는 없다:

```text
ID1~16
2020 3173 2574 2990 1937 2066 3145 1971
1867 2055 3178 1981 2911 2227 3203 1879
```

원본 세로1268목표는 바꾸지 않고 보존했다. vertical_pitch_order_20261118.py에서 검지·중지 뿌리 올림을 엄지 내림/후퇴 뒤로 옮긴1507목표 수정본을 만든다. 엄지 내림 동안 다른14개 관절의 해당 원본 목표값은 유지하고 ID8/12만 시작 각도에 둔다. 마지막252목표와 끝 자세는 원본과 같다. 450mA/PID/2틱75ms/500초 및 상태·추종·진행·읽기 기준은 그대로며 새 범위 확대는 없다.

소프트웨어 검사15개 통과: 준비 이송 순서와 G시작,엄지 내림 동안 ID8/12고정,엄지 내림 뒤 뿌리 올림,새 확인점에서 이상 시 올림 미진입/OFF·설정복구,원본 마지막252목표·끝자세 보존,출처/2틱/범위/시간/중간OFF검사 등을 확인했다. 정적 비교에서 새 큰 손가락 간섭은 없었고 기존 엄지·손바닥 약0.14mm 및 받침 프록시 겹침은 남는다. 형상 삭제는 없고 전체 큐브 동역학이나 실물 새순서 성공을 증명하지 않는다.

결과 폴더는 `vertical_transfer_trial_날짜_시각/`다. 가로 실물 성공 경로 및 확정 G는 그대로 보존했다. 이번 실물 확인 대상은 이송 경유 자세에서 큐브를 유지한 채 세로 회전을 시작해 끝낼 수 있는지다.
