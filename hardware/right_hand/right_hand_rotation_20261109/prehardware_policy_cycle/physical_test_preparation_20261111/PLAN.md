# 오른손 단계별 실물 진단 준비 — 2026-11-11

연결 후 갱신: 실제16모터 읽기와 현재진입 경로 정적201/동적9조건을 통과했다. 기존 정회전→10초 유지의 사용자용 첫시험 명령 `leap_cycle_stage1_forward_hold.cmd`를 준비했다. 사용자 추가 각도조정 뒤 실제 카메라 사진을 확인해 첫 진단용 구도를 수용했다. 실제 움직임은 아직 없다. 최신 절차는 [STAGE1_GUIDE.md](STAGE1_GUIDE.md), 원본은 `connected_20261111_214517_052288/current_review.json`, `camera_framing_review.json`, `stage1_verification.json`이다. 아래는 최초 연결 전 준비 기록이다.

사용자는 전체 회전 → 유지 → 다음 회전 → 유지의 실물 시험을 시작하고 싶다고 요청했다. 완성 전에도 구간별 진단 시험은 가능하다. 모델 오차 내성이 전부 해결돼야만 실물을 관찰할 수 있다고 안내하지 않는다.

현재 준비한 것은 **읽기 전용 사전 점검 명령**이다. 새 전체 동작의 움직이는 실행 명령은 아직 준비 완료가 아니다.

1. 로봇 USB·웹캠과 모터 전원을 연결한다. 다른 모터 프로그램은 종료한다. 현재 조사에서는 Bluetooth COM3/COM4만 있었고 알려진 로봇 어댑터는 없었다. COM7을 임의로 고르지 않는다.
2. `leap_cycle_test_readonly.cmd`를 열고 SPACE를 누르면 알려진 USB 어댑터에서 1Mbps PING/READ만 수행한다. 16개 모터 응답, 토크·오류·watchdog, 현재 각도·전압·온도와 현재 설정을 읽고 포트를 닫는다. 토크/목표/모드/PID/제한을 쓰지 않는다. 결과는 새 `cycle_test_readonly_날짜_시간/result.json`에 저장한다. 보조자가 연결 후 동일 도구의 `--read`로 읽기 전용 점검을 수행할 수도 있다.
3. 저장된 실제 시작 자세와 카메라 배치를 검토해 첫 짧은 이동 구간과 유지 종료점을 정한다. 최신 경로를 바로 실행하거나 기존 전체 시퀀스의 완료 표시를 바꾸지 않는다. 실제 시작값 없이 어느 과거 진입 자세를 그대로 사용할지 단정하지 않는다.
4. 기존 450mA/PID/최대2틱/75ms 및 전압·전류·추종·통신 중단 기준을 유지하는 진단 실행기를 별도 검토한다. 사용자가 `.cmd`와 SPACE로 시작한다. 첫 구간 → 유지 관찰 → 결과 검토 순서로 진행하고, 확인된 범위에서 첫 회전 → 유지 → 두 번째 회전으로 확장한다. 유지 중 제어를 계속하고, 실험 종료 후 토크 OFF는 정상 정리로 취급한다.

읽기만 성공했다고 회전 준비 완료가 되는 것은 아니다. 사전 점검 뒤 실제 자세를 기준으로 첫 움직임의 입력과 종료 조건을 확인해야 한다. 기존 중지 진단 완료 실험이나 옛 3Mbps 점검을 사용자에게 다시 시키지 않는다.

모델에서는 명목 조건 5089목표와 마찰0.25 가정 9614목표의 두 회전·두 유지가 성공한 기록이 있다. 후자의 새 경로는 작은 마찰·배치 변화에서 실패했으므로 약12분 전체 자동 실행의 실물 승인으로 사용하지 않는다. 특정 손끝의 접촉을 무조건 유지할 필요는 없고 손바닥·뿌리를 포함한 손 전체가 지지하면 된다. 같은 위치2mm 복귀는 오른손 단독 시험의 선행 조건이 아니다. 왼손 도달·하중 시험은 통합 때 별도로 확인한다.

현재는 포트 목록만 확인했다. 이번 준비에서 실제 PING/READ·카메라 열기·모터 출력은 수행하지 않았다. 새 SAC 학습·증류·정책 전송도 수행하지 않았다.
