## 확인된 차이

| 항목 | 현재 정책 시험 | 기록 시퀀스 |
|---|---|---|
| 자세 기준 | 학습 DEFAULT_POSE 기반 준비 | 수동으로 기록한 7개 자세 |
| 이동 | 준비 자세에서 ±0.0997rad, 명령당 최대32틱 | 연속 자세 간 최대 관절 변화0.794~1.721rad |
| 시간 | 정책5초, 명령 주기 목표50ms | 각 전환70회×sleep30ms=최소2.1초, 통신 시간 별도 |
| 제어 | 카메라·엔코더 입력으로 정책 계산 | 단계 시작 실제각에서 다음 저장각까지 선형 보간 |
| 실물 결과 | 14:20 사용자는 큐브가 손바닥에 그냥 있었다고 보고 | 사용자가 뒤집기 성공 경험 보고 |

기록 시퀀스의 nominal 최대 관절 보간 속도는 단계별0.378~0.820rad/s.
이는 코드상 목표 변화 속도이며 실제 측정 속도가 아니다. 현재 시험9회 전송 중
마지막15관절 목표가±65틱 경계였다. 명령 전송 완료와 큐브 조작 성공을 구별한다.

## 현재 코드에 적용할 때의 구분

- LeapNode의 실제 motors 배열은 ID1..16, set_leap는 배열을 그대로 전달한다.
  main.py의 옛 배선 주석/side ID8·12·16 설정과 현재 검증된 side ID6·10·14가
  다르므로 주석이나 PID 설정을 복사하지 않는다. ID별 숫자 자세는 비교 자료로 보존한다.
- 첫 저장 자세는 현재 sim 변환/관절 한계 내이고, 현재 준비 자세와 최대1.054rad 차이.
  관절 한계 내라는 사실이 전체 이동 경로/접촉 검증을 뜻하지는 않는다.
- 나머지 자세는 주로 ID7·11의 현재 PIP 하한(-0.2rad)을 벗어난다.
  최대 약-0.376rad이며, 세번째 자세는 ID4가1.995rad로 현재 상한1.88rad도 초과.
  조용히 clipping하면 사용자 성공 시퀀스와 다른 동작이므로 동일 성공을 가정할 수 없다.
- 로컬 main.py는 초기화 중 torque ON/450mA/P600/D200 등을 쓴다. 현재550mA와
  장치 PID 보존 동작을 대체해서 실행하지 않는다.

## 다음 작업 방향

같은 작은 정책 동작 시험을 반복하거나 전류를 올리는 대신, 첫 저장 자세를 실제 파지의
참고로 사용해 현재 학습 시작 자세/관측과의 차이를 검토한다. 이후 파지 준비 경로와
정책 제어를 구분해서 연결한다. 학습하지 않은 초기 자세를 정책에 곧바로 넣으면 성능이
달라질 수 있으므로, 시퀀스의 성공을 그 자세에서 SAC도 성공한다는 근거로 삼지 않는다.
전체 시퀀스는 이동량·속도·접촉 순서의 기준이며 SAC 자체나 재학습이 된 것은 아니다.

숫자 자료: `sequence_flip_reference_analysis.json`.
현재 자동 실행 파일이나 동작 범위는 변경하지 않았다. 사용자에게 같은 시험 재실행을 요청하지 않는다.
