# VS Code Codex 작업 인계

아래는 2026-11-06까지 진행한 로컬 작업의 인계문이다. 한국어로 대화해 줘. 사용자가 별도로 제공하지 않은 소스와 사진, 대화 원문까지 읽었다고 가정하지 말고 실제 접근 가능한 파일에 근거해 작업해 줘.

## 지금 먼저 할 일

사용자는 현재 VS Code Codex의 대화와 프로젝트를 Codex 웹과 다른 PC에서도 이어가려 한다. GitHub 계정은 이미 있으며 개인 계정에 먼저 올리고 팀 또는 프로젝트 쪽으로의 이전은 나중에 한다. **2026-11-07에 비공개 저장소 `https://github.com/star1209042/xlerobot`로 코드와 모델 및 인계 자료를 실제 업로드했고 원격 커밋을 확인했다.** 브랜치는 `main`과 `codex/cloud-handoff-20261106`이다.

현재 다음 단계는 이 저장소를 선택해 Codex 클라우드 환경을 만들고, `bash cloud/setup.sh`로 의존성과 저장 모델 검사를 확인한 뒤 환경을 게시하는 것이다. **클라우드 환경 생성이나 실제 클라우드 계산은 아직 확인하지 않았다.** 계정이나 GitHub CLI 로그인부터 다시 요구하지 말고 웹의 저장소 연결 상태를 구분한다. 환경 준비 순서는 `cloud/SETUP.md`, 첫 로봇 분석 요청은 `cloud/START_PROMPT.txt`에 있다.

원래 Windows의 `files-mentioned-by-the-user-leap/outputs` 폴더는 설치 환경 등을 제외해도 약 38.7GB였다. 업로드는 그중 원본 3,519개 파일 약 496MB와 안내 파일을 선별한 것으로 전체 백업은 아니다. 원본 작업 자료를 보존했고 계정 인증 정보와 실행 환경 및 대부분의 원시 영상을 올리지 않았다. 원본 코드와 결과의 SHA256 및 포함 범위는 `cloud/upload_manifest.json`에 있다. 현재 동작에 결합된 170개 원본 해시가 유지된다.

이 인계문은 대화 원문 전체의 자동 동기화를 뜻하지 않는다. IDE에서 새 클라우드 작업으로 맥락을 넘기는 기능과 웹 새 대화에 인계문을 붙여 넣는 방식은 구분한다. 클라우드에서 원래 PC의 USB나 웹캠에 접근할 수 있다고 가정하지 않는다. 나중에 팀/조직으로 저장소 소유권을 옮기거나 기존 팀 저장소에 코드를 합치는 것은 별도 작업이다.

## 로봇 목표와 사용자 선호

- 더 큰 프로젝트는 양손 큐브 맞추기다. 지금 양손 통합이나 전체 풀이가 완료된 상태는 아니다.
- 사용자는 자신이 할 물리 작업이 생기기 전까지 가능한 분석과 수정을 계속해 주길 원한다. 매번 로그 전체를 다시 붙여 달라고 하지 말고 접근 가능한 저장 결과부터 확인한다.
- 기존에 실제로 회전했던 기록과 원본 시퀀스를 계속 참고한다. 모델 검사 통과와 실제 큐브 회전 성공을 구분한다.

실물의 일부 방향 회전과 유지 관찰 기록은 있으나 원하는 모든 방향, 공통 하부 파지, 윗단 하중 및 다음 회전의 연결은 아직 검증해야 한다. 방향 변경과 윗단 한 층 회전을 혼동하지 않는다.

## 모터 대응과 실물 조건

손끝에서 손바닥 순서:

- 엄지: 1, 2, 3, 4
- 검지: 5, 7, 6, 8
- 중지: 9, 11, 10, 12
- 약지: 13, 15, 14, 16

시뮬레이션 순서의 모터 ID는 `(8,6,7,5,12,10,11,9,16,14,15,13,4,3,2,1)`이며 `qsim=(ticks-2048)*2π/4096`다. 초기에는 잘못된 대응으로 분석한 기록이 있으므로 위 최신 대응을 사용한다.

큐브 한 변 55mm, 손끝은 단단한 플라스틱이다. 마찰 0.3은 가정이며 측정값이 아니다. 현재 고정 손 본체 밑에는 20mm 책이 있고 원래 받침의 유리는 6mm다. 실제 받침을 임의로 옛 34mm 또는 50mm 치수로 되돌리지 않는다. 최근 모델의 받침 앞끝 조건은 해당 검증 파일을 확인한다. ID40은 손바닥 마커여서 큐브에 가려질 수 있다. ID41은 손목 마커, 검은 사각형 약 27mm이며 큐브 마커는 약 10.7mm다.

실물 모터는 XC330-M288 16개, 최근 통신은 1Mbps 및 원래 PC의 COM7이다. 장치명과 포트 번호를 다른 PC에 그대로 적용하지 않는다. 웹캠은 별도 USB `Streaming Webcam`이다.

## 실행 경계와 남은 일

현재 물리 명령은 사용자가 원래 PC에서 `.cmd`와 SPACE로 시작한다. 보조자가 직접 하는 장치 접근은 읽기 전용으로 구분해 왔다. 클라우드에서 로컬 USB나 웹캠이 연결된 것으로 가정하지 않는다. 저장 자료 분석과 오프라인 시뮬레이션은 계속할 수 있다.

실물은 준비된 경로를 재생하며 카메라로 알아서 위치를 보고 실시간 SAC가 학습해서 조작하는 상태가 아니다. 새 학습이나 실물 정책 전송이 완료됐다고 말하지 않는다.

450mA 및 기존 PID, 최대 2틱 목표 간격, 최근 75ms 주기, 전압과 전류 및 추종 중단 기준을 유지한다. ID4 하한 -2도는 사용자가 승인한 변경이며 다른 관절의 제한을 함께 넓히지 않는다. 과거 한두 틱 읽기 지연이나 OFF 처짐에 대한 복구는 이미 별도 구현돼 있으므로 로그에서 실제 실패 원인을 확인하고 조정한다. 충돌 형상을 통째로 빼거나 한계값을 무작정 낮추어 완료로 만들지 않는다.

로봇 작업의 다음 순서:

1. 최근 중지 진단 사진에서 큐브 유지와 윗단 공간의 변화를 확인한다.
2. 엄지 위치와 중지 굽힘을 분리해 하부 파지와 윗단 회전 공간을 함께 확보한다.
3. 원하는 방향 회전 뒤 같은 작업 파지로 돌아오는 경로를 연결하고 배치 및 구동 오차를 시험한다.
4. 실물에서 검증한 뒤 다른 손의 실제 윗단 회전 하중과 양손 간섭을 통합 시험한다.

진행 상황 원본은 `professor_progress_20261015.md`이며 최신 항목을 먼저 읽는다. 옛 기록의 다음 사용자 작업을 현재 명령으로 반복하지 않는다. 근거 없는 완료율이나 2~5일 내 완성 보장을 하지 않는다.
