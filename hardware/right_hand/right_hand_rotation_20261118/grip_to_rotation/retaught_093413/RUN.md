# 새로 가르친 엄지 후퇴·큐브 이송 자세

실행파일은 루트의 `leap_grip_to_rotation.cmd`다. 09:34에 사용자가 만든 16관절 자세를 새 기준으로 사용한다. 현재 목표가 이 기록과 최대 4틱 이내이면 지금 자세를 이어받아 유지하고 첫 큐브 위치 확인을 기다린다. 이미 토크 ON이면 초기 OFF를 하지 않는다. 다른 자세에서 시작하면 기존 G 파지를 거쳐 16개 관절을 새 이송 자세로 함께 옮긴다. 옛 엄지 단독 후퇴/검지·중지 받침/약지 밀기 목표는 새 경로에 넣지 않았다.

새 이송 자세에서 큐브 지지와 자리를 확인하고 SPACE → 검지 회전 준비 → 확인 SPACE → 엄지가 받기 → 확인 SPACE → 중지·약지 인계 → 회전 시작 파지/큐브 자리 확인 SPACE → 기존 가로 회전 → 끝 자세 유지 순서다. 움직이는 도중 SPACE/Q/Esc는 중단/OFF이며, 끝 자세에서는 큐브를 받친 뒤 SPACE로 종료한다. 이번 실행에 확정 G 복귀 및 자동 반복은 포함하지 않았다. 새 자세까지 이동하고 유지하는 관찰만 하려면 `leap_grip_transfer_only.cmd`를 쓴다.

저장한 토크 ON 목표 ID1~16:

```text
2538 2814 2883 2321 3141 2011 3149 1818
3165 2209 3191 1833 2790 3009 3254 2600
```

원본은 `receiving_waypoint_readonly_20261118_093413_840315/result.json`과 `current_pose.png`다. 모터 쓰기 0회, 토크 변경 0회, 16개 모두 ON/오류 0, 두 번 위치 차이 최대 1틱, 위치와 유지 목표 차이 최대 4틱을 확인했다. 사진은 읽기 후 촬영했으므로 정밀 동기 측정은 아니다.

기록값을 임의로 줄이지 않았다. 이 실행 프로세스에서만 ID8 하한1818/ID12 하한1833/ID14 상한3009틱까지 정확한 실측 목표를 허용한다. 추가 여유는 없고 원래 범위 파일·EEPROM·다른 실행파일의 범위는 바꾸지 않았다. 프로세스의 적용 구간이 끝나거나 예외가 나면 기존 소프트웨어 범위로 돌아간다. 450mA/기존 PID/최대2틱/75ms 및 기존 상태·전류·전압·추종·읽기·진행·시간 중단 검사는 유지한다.

가상 버스 검사 10개는 현재 자세에서 G로 돌아가지 않는 동작, G에서 새 16관절 목표로 함께 이동, 기존772개 회전 목표 보존, 확인 대기, 회전 전 이상 시 중단/OFF·설정 복구, 정확한 측정 범위와 범위 복구, 출처 변경 거부를 확인했다. 소프트웨어 검사 통과는 큐브 이송/회전 성공 인증이 아니다.

모델 진단은 기존 G 시뮬레이션의 큐브 위치를 가정했다. 새 자세 부근에서 추종 회복이 안 돼 index325에서 중단됐다. 모델은 중지 끝·손바닥 겹침을 최대1.33mm, 받침 프록시 겹침을 최대7.20mm로 계산했고, 같은 겹침 최대값이 지금 실물에서 읽은 끝 자세의 각도를 직접 넣어도 나온다. 실제 접촉 및 받침 정합이 미검증이므로 이 차이를 실제 충돌/무충돌로 단정하지 않는다. 충돌 형상은 유지했고 진단 결과는 `model_review.json`에 보존했다. 전체 모델 검사 통과로 기록하지 않으며 실제 전환·회전은 단계별 관찰 대상이다.

결과는 `retaught_transfer_trial_날짜_시각/`에 저장된다. 확정 G와 이미 성공 관찰한 기존 회전→G 실행파일은 그대로 보존했다.
