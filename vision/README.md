# 마커 가이드

큐브와 손에 붙일 ArUco 마커의 제작·부착·검증 절차입니다.
전체 맥락은 `../docs/실기이관_평가_가이드.pdf` 5절을 보십시오.

---

## 1. 어느 파일을 인쇄하는가

| 큐브 | 파일 | 배치 |
|---|---|---|
| **3x3 루빅큐브** (나중에 돌릴 것) | **`rubik_center/center_markers_A4.pdf`** | 면당 중앙 1개 |
| 일반 큐브 / 평가 전용 큐브 | `general_2x2/faces_A4.pdf` | 면당 2x2 = 4개 |

**PNG 가 아니라 PDF 를 인쇄하십시오.** PDF 는 A4 페이지에 정확히 맞춰져 있어
배율이 틀어질 여지가 적습니다. PNG 는 뷰어마다 다르게 확대됩니다.

### 루빅큐브는 왜 중앙만인가

**코어에 고정된 것은 6개 중앙 조각뿐**입니다. 코너·엣지는 면을 돌리면 자리가
바뀌므로 마커를 붙이면 보드 정의가 깨집니다. 면을 가로지르는 마커는 한 층만
돌려도 찢어집니다.

---

## 2. 크기 — 큐브를 먼저 재십시오

마커는 스티커의 **75%** 까지입니다. 4x4 사전은 6x6 셀이라 콰이어트 존(흰 여백)
1셀을 확보하려면 `marker + 2*(marker/6) <= sticker` 이기 때문입니다.

`rubik_center/center_markers_A4.pdf` 에는 **세 줄**이 들어 있습니다. 중앙 스티커를 자로 재고
맞는 줄만 쓰십시오.

| 스티커 | 마커 | 720p/30cm | 720p/40cm | 1080p/30cm |
|---|---|---|---|---|
| 15 mm | 11.25 mm | 42 px | 31 px | 62 px |
| 16 mm | 12.00 mm | 44 px | 33 px | 67 px |
| 17 mm | 12.75 mm | 47 px | 35 px | 71 px |

4x4 사전의 검출 하한은 약 **40 px** 입니다.

> **720p 를 40cm 에 두면 미달입니다(31~35 px).** 30cm 까지 당기거나 1080p
> 카메라를 쓰십시오. 각도가 붙으면 더 놓칩니다.

일반 큐브(2x2 배치)는 57mm 면 기준 **20mm** 입니다. 22mm 는 면 가장자리 여백이
0.89셀로 부족합니다.

---

## 3. 인쇄

1. **"실제 크기" / "100%"** 로 인쇄합니다. "페이지에 맞춤"은 금물입니다.
2. **무광 용지.** 광택지는 조명 반사로 검출이 끊깁니다.
3. 인쇄 후 시트 맨 위 **50 mm 눈금자를 자로 재십시오.** 50 mm 가 아니면
   배율이 틀린 것이고, 그대로 쓰면 **거리 추정이 그 비율만큼 통째로 틀립니다.**
4. 마커 한 변도 재서 표의 값과 맞는지 확인합니다. 다르면 그 실측값을
   `cube_board.py` 의 `MARKER_MM` 에 넣으십시오.

---

## 4. 붙이기

### 4.1 큐브에 축을 먼저 정합니다

한 면을 **+z**, 인접한 두 면을 **+x**, **+y** 로 잡아 오른손 좌표계를 만듭니다.
연필로 모서리에 표시해 두십시오. 이 축이 시뮬의 큐브 좌표계와 대응합니다.

### 4.2 ID 를 면에 맞춥니다

**중앙 배치 (루빅큐브)** — ID 가 곧 면 번호입니다.

| ID | 면 |
|---|---|
| 0 | +z |
| 1 | -z |
| 2 | +x |
| 3 | -x |
| 4 | +y |
| 5 | -y |

**2x2 배치 (일반 큐브)** — `ID // 4 = 면 번호` 입니다. 면 0 은 ID 0~3.

타일 바깥 사각선을 따라 자르면 스티커와 같은 크기라 기존 스티커 위에 그대로
덮입니다.

> ID 와 면이 어긋나면 **목표 면이 통째로 뒤바뀝니다.** 정책은 3번 면을 맞추라는
> 명령을 받고 5번 면을 맞추게 됩니다.

### 4.3 방향

**중앙 배치는 방향을 신경 쓰지 않아도 됩니다.** 12mm 급 마커에는 방향 표시를
넣을 여백이 없어서, 대신 붙인 뒤 `calibrate_face_rot.py` 로 측정합니다(6절).

**2x2 배치는 방향이 중요합니다.** 각 템플릿의 **+u,+v 꼭지에 검은 삼각형**이
찍혀 있습니다. 그 삼각형이 해당 면의 u 축과 v 축이 만나는 꼭지에 오도록
붙이십시오.

| 면 | u (오른쪽) | v (위) |
|---|---|---|
| 0 `+z` | +x | +y |
| 1 `-z` | -x | +y |
| 2 `+x` | +y | +z |
| 3 `-x` | -y | +z |
| 4 `+y` | +z | +x |
| 5 `-y` | -z | +x |

### 4.4 손 기준 마커 (ID 40, 30 mm)

**`rubik_center/center_markers_A4.pdf` 맨 아래에 이미 들어 있습니다**(30 mm). 따로 인쇄할
필요 없습니다. **손등이나 손목 베이스에 수평으로**
붙이십시오. 두 가지를 해결합니다.

- 관측이 `손바닥 - 큐브` 인 **상대량**이라, 손에 마커가 있으면 카메라 위치를
  정밀하게 고정하거나 캘리브레이션할 필요가 없습니다. 노트북을 건드려도
  값이 유지되고, 카메라 여러 대가 서로 좌표를 맞출 필요도 없습니다.
- 면 오차가 **중력 기준**이라 월드 up 이 필요한데, 수평으로 붙이면 마커의
  법선을 쓸 수 있습니다.

## 5. 반드시 재서 넣어야 하는 값 두 개

`rubik_center/track_cube.py` 상단입니다. 기본값으로 두면 **위치 관측이 그만큼 틀립니다.**
성공 임계값이 15 mm 라 무시할 수 없습니다.

| | 뜻 | 기본값 |
|---|---|---|
| `PALM_IN_MARKER` | 손 마커 프레임에서 본 손바닥(grasp_site) 위치 [m] | `0,0,0` |
| `HAND_TO_WORLD` | 손 마커 프레임 -> 시뮬 월드 회전 | 단위행렬 |

`PALM_IN_MARKER` 를 0 으로 두면 마커 위치를 손바닥으로 간주하는 것입니다.
`HAND_TO_WORLD` 는 마커를 손등에 수평으로, u 축을 시뮬 +x, v 축을 +y 로 맞춰
붙이면 단위행렬 그대로입니다.

카메라가 주는 자세는 **카메라 프레임**이고 정책이 먹는 관측은 **월드 프레임**
입니다. `track_cube.py` 가 손 마커를 기준으로 돌려 월드로 옮기며, 위 두 값이
그 변환의 나머지 절반입니다.

## 6. 캘리브레이션 두 가지

### 6.1 카메라 내부 파라미터 (카메라마다 1회)

체스보드를 9x6 내부코너로 A4 에 100% 인쇄하고 한 칸을 자로 재서
`rubik_center/calibrate_camera.py` 의 `SQUARE_MM` 에 넣습니다. **이 값이 틀리면 이후 모든
거리 추정이 같은 비율로 틀립니다.**

```bash
cd rubik_center
mkdir calib0   # 각도·위치 바꿔가며 20~30장 촬영. 화면 구석까지 채울 것
python calibrate_camera.py "calib0/*.jpg" camera0.npz
```

재투영 오차가 **0.5 px 이하면 양호, 1.0 px 를 넘으면 다시** 찍으십시오.

### 6.2 면별 마커 회전 (중앙 배치에서 필수)

붙인 방향을 측정합니다. 그리고 **면을 돌리면 그 면의 중앙 조각이 제자리에서
90도 회전**하므로, **스크램블한 뒤에는 이것을 다시 돌려야 합니다.**

큐브를 여러 자세로 들고 **두 면 이상 보이는 프레임 15장**을 모으면
4^6 = 4096 후보를 전수 탐색해 재투영 오차 최소를 고릅니다. 한 면만 보이는
프레임은 그 면의 회전이 자세와 구별되지 않아 정보가 없으므로 버립니다.

```python
import cv2, numpy as np, calibrate_face_rot as cal, track_cube as tc
d, board, det = tc.build(marker_mm=12.0, grid=1)
cap = cv2.VideoCapture(0)
obs = cal.collect(cap, det, n=15)
z = np.load("camera0.npz")
face_rot, err = cal.solve(obs, z["K"], z["dist"], marker_mm=12.0)
```

합성 검증에서 코너 잡음 1 px 까지 참값을 정확히 복원했습니다.

## 7. 검증

붙이고 나면 이 다섯 가지를 확인하십시오.

1. 큐브 **+z 를 위로** 들었을 때 `face_up` 이 **0** 인가
2. 90도 돌려 **+x 를 위로** 했을 때 `face_up` 이 **2** 인가
3. 자로 잰 손-큐브 거리와 추정값이 **5 mm 이내**인가
4. 큐브를 정지시키고 100프레임 -> **자세 표준편차가 5.7도보다 작은가**
   (학습 시 주입한 잡음이 5.7도다. 이보다 크면 정책 입력으로 못 쓴다)
5. 손으로 가려가며 -> 카메라 1대와 2대의 **검출 성공률 차이**

5번이 가장 중요합니다. 중앙 배치는 면당 마커가 1개인데 하필 **손가락이 가장
자주 닿는 자리**라 가림이 지배적인 실패 원인입니다.

## 8. 다시 만들기

```bash
pip install opencv-contrib-python

cd rubik_center  && python make_center_templates.py   # 루빅큐브 중앙 (스티커 15/16/17mm)
cd general_2x2   && python make_face_templates.py     # 일반 큐브 2x2 (면 57mm, 마커 20mm)
cd general_2x2   && python make_markers.py 20 2       # 낱개 마커 시트
```

크기를 바꾸려면 `make_center_templates.py` 의 `STICKERS`, 또는
`make_face_templates.py` 의 `cb.CUBE_MM` / `cb.MARKER_MM` 을 고치십시오.
**`cube_board.py` 의 값과 반드시 일치해야 합니다** — 인쇄물과 3D 좌표가 다른
것을 가리키면 자세가 조용히 틀립니다.

PDF 로 다시 굽는 방법:

```bash
xelatex -output-directory=/tmp mk.tex   # A4 페이지에 이미지를 210x297mm 로 배치
```

## 9. 검출이 안 될 때

| 증상 | 원인 | 조치 |
|---|---|---|
| 아무것도 안 잡힌다 | 마커가 너무 작다 | 2절 표 확인. 카메라를 당기거나 1080p |
| 가끔 끊긴다 | 노출 자동 | 노출·초점 **수동 고정**. 어두우면 15fps 로 떨어진다 |
| 반짝일 때 놓친다 | 광택지 정반사 | 무광 용지, 조명 각도 변경 |
| 거리가 일정하게 틀리다 | 인쇄 배율 | 눈금자 50mm 재확인 |
| 자세가 카메라마다 다르다 | 프레임 변환 누락 | `palm_minus_cube`/`cube_quat_world` 를 쓸 것 (`rel_cam` 아님) |
| 두 면 보일 때 튄다 | `face_rot` 미보정 | 6.2 실행. 스크램블 후에도 다시 |
| 목표 면이 엉뚱하다 | ID-면 대응 오류 | 4.2 표 재확인 |

## 10. 폴더 구성

두 경로로 갈라 두었습니다. **하나만 쓰면 됩니다.**

### `rubik_center/` — 3x3 루빅큐브. **현재 이것을 씁니다**

| 파일 | 내용 |
|---|---|
| `center_markers_A4.pdf` / `.png` | **인쇄할 시트.** 스티커 15/16/17mm 3종 + 손 마커(ID 40, 30mm) |
| `make_center_templates.py` | 위 시트 생성기 |
| `cube_board.py` | 보드 3D 좌표. `layout="centers"` / `"grid"`, `face_rot` |
| `calibrate_camera.py` | 카메라 내부 파라미터 |
| `calibrate_face_rot.py` | 면별 마커 회전 (중앙 배치 전용) |
| `track_cube.py` | 자세 추정 + **카메라→월드 프레임 변환** |
| `multi_camera.py` | 여러 대 그래버 + 융합 |

공용 코드가 여기 들어 있습니다. `deploy/policy_runner.py` 와 `tests/` 가
이 폴더를 import 합니다.

### `general_2x2/` — 일반 큐브. **지금은 쓰지 않습니다**

3x3 루빅큐브에는 **쓸 수 없습니다.** 마커가 여러 큐비에 걸쳐 있어 한 층만
돌려도 찢어집니다.

| 파일 | |
|---|---|
| `faces_A4.pdf` / `.png` | 2x2 면 템플릿 6면 (면 57mm, 마커 20mm) |
| `face0_pz.png` ~ `face5_my.png` | 위의 면별 개별 파일 |
| `make_face_templates.py` | 생성기 |
| `markers_A4.pdf` / `.png` | 낱개 마커 25개. 손 마커까지 중복 |
| `make_markers.py` | 생성기 |

**남겨 둔 이유**: 중앙 12mm 마커는 720p 를 40cm 에 두면 33px 로 검출 하한에
못 미칩니다(2절). 카메라를 못 바꾸는 상황이면 **평가 전용 큐브를 따로 두는 것**
이 가장 실용적인 대안이고, 그때 이 폴더가 그대로 필요합니다.

이 폴더의 생성기는 `../rubik_center/cube_board.py` 를 import 합니다.
