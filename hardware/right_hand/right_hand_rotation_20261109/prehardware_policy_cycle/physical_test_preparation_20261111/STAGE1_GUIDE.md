# 첫 실물 진단: 기존 정회전 → 10초 유지

실행 후 갱신: 사용자가2026-11-11 두 번 실행했다. 첫 시행은 사용자 보고의 배치 오류로 목표 평가에서 제외하고, 두 번째의 첫 회전→약10초 손 위 지지 유지와 정상 종료를 저장 사진·로그에서 확인했다. 같은 첫 시연을 현재 사용자 작업으로 반복하지 않는다. 최신 검토는 `right_hand_rotation_20261111/stage1_actual_review/REVIEW.md`다. 아래는 해당 시험의 실행 안내 기록이다.

2026-11-11 연결 후 COM7의 알려진 USB 어댑터를 1Mbps로 조회했다. 모터16개 모두 모델1240 응답, 토크OFF, 하드웨어 오류0, 전압5.0~5.1V, 온도18도, 두 번 읽은 각도 차이0틱이다. 목표·토크·설정은 쓰지 않았고 포트를 닫았다.

실제 시작 자세를 입력으로 기존 진입 경로를 새로 검사했고 정적201조건/동적9조건이 통과했다. 현재 각도는 기존 설정 범위 안이다. 엄지 뿌리 ID4=1839틱(기준2048틱 대비 약−18.37도)은 이번 시작에서 기존 범위를 확대해야 하는 문제가 아니다.

이번 첫 시험은 **실제 회전 기록이 있는 기존 정회전 지령과10초 유지**다. 새 두 회전 전체 연결·윗단 공간 확보·왼손 통합 성공을 확인하는 명령이 아니다. 450mA/PID/최대2틱/75ms와 기존 통신·전압·전류·추종 중단 기준을 그대로 사용한다. 기존 코드와 결합 자료를 수정하지 않았다.

사용자가 카메라 각도를 추가 조정한 뒤 `Streaming Webcam`1280×720 MJPG 사진을 다시 촬영해 확인했다. 최신 `camera_retry_1794401740498897300.jpg`에는 손바닥·엄지·세 손가락과 큐브를 놓을 자리가 보여 첫 진단 관찰용 구도로 수용했다. 위쪽 손끝은 화면 가장자리와 가까우므로 프로그램 준비 자세의 실시간 화면도 확인한다. 모든 이동 자세가 화면 안에 든다는 인증이나 정밀 좌표 정합을 뜻하지 않는다. 카메라와 포트는 모두 닫았고 모터 출력은 보조자가 직접 시작하지 않는다. 판독 기록은 `connected_20261111_214517_052288/camera_framing_review.json`이다.

구도 확인 후 `leap_cycle_stage1_forward_hold.cmd`를 실행한다.

1. **첫 SPACE: 빈손 준비.** 큐브를 손 밖에 둔다. 프로그램이 현재OFF각도를 다시 읽고 모델 검사를 한다. 통과하면3초 카운트 뒤 준비 자세로 움직인다. 실제 시작이 달라져 검사를 통과하지 못하면 실행하지 않는다.
2. **PLACE 안내 뒤 배치하고 두 번째 SPACE.** 초록색 면이 위, 주황색 면이 손목ID41 쪽이 되도록 놓는다. 손을 뗀 뒤 SPACE를 누르면 기존 파지 → 정회전 → 같은 목표각10초 유지까지 수행한다.
3. **유지 완료 안내 뒤 큐브 아래를 받치고 세 번째 SPACE.** 토크OFF와 설정 복구가 끝나면 큐브를 뺀다. 자동OPEN이나 역회전은 없다. Q/Esc/Ctrl+C는 중단한다.

오늘 시작값으로 만든 경로의 순수 지령 시간은 약171초이며 배치 대기·모델 검사·종료 확인 시간은 별도다. 시험 결과의 관절 기록과 영상으로 실제 회전·유지 상태를 판단한 뒤 다음 구간을 정한다.

근거는 `connected_20261111_214517_052288/prepare.json`, `forward_hold_request.json`, `current_review.json`, `empty_recovery_screen/review.json`이다. 실제 읽기 원본은 루트의 `cycle_test_readonly_20261111_214517_052288/result.json`이다. 카메라 첫 저장은 한글 경로를 받는OpenCV직접저장 실패로 기록됐고, 인코딩 후Python파일저장으로 다시 촬영·저장했다. 실패 기록을 보존했다. 카메라 좌표 정합이나 실제 시험 성공으로 세지 않는다.
