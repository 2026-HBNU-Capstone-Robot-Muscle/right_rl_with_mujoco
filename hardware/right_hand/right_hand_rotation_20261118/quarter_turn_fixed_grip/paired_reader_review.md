# 통신 읽기 방식 개선

`grip_health_read_20261118.py`를 추가하고 새 파지/회전 실행기의 `PoseBus`에 연결했다. 기존 원본170개 파일, 회전/파지 관절 목표와 모터 설정 기준은 바꾸지 않았다.

- 보통 Sync READ의 응답 묶음을4개에서2개 모터로 줄였다. 최대 응답 묶음은 약376바이트에서188바이트로 줄며 한 번의 전체 상태 읽기는 여전히16개 모터를 모두 요구한다. 요청 수는4회에서8회로 늘어난다.
- 호스트 시리얼 읽기를1ms의 짧은 대기로 바꿨다. USB 드라이버/레지스트리/모터 레지스터는 변경하지 않는다.
- SDK의 CRC·바이트 스터핑·모터별 오류 검사를 그대로 쓰고, 실패한 원시 패킷은 최대64개 저장한다. 다음 실패 때 실제 CRC 불일치와 부분 수신/시간 초과를 구분할 수 있도록 길이와 CRC 비교도 기록한다.
- 공유200ms 읽기 기한, 오류 후 새 전체 상태 연속2회 확인,10초당 재시도3회, 불완전 상태에서 목표 진행 금지,450mA와 기존 건강 감시는 유지했다.

기존 방식의 정지 상태 읽기160회는 오류0이었다. 따라서 과거 실행 중 오류의 물리 원인이 확정되거나 이 변경으로 근절됐다고 주장하지 않는다. 작은 응답 묶음과 호스트 대기로 수신 동작을 바꾼 수정이며, 실제 동작 중 재확인이 필요하다.

검사47개 통과: 실제 SDK 파서에 조각난/스터핑된 응답, CRC 손상, 모터 누락, 장치 오류, 공유 기한 초과를 주입했다. 기존 복구/재시도율/파지 경로/SPACE 대기/중단 후 OFF·설정 복구 검사도 포함한다. 두 실행기의 장치 없는 시작 검사도 통과했다. 로그는 `paired_reader_checks.log`다.

수정본의 실제 토크OFF 읽기400회를 완료했다. 오류0,전체상태 읽기31.43~33.47ms,모터쓰기0/토크변경0이다. 근거 `grip_read_diagnosis_20261118_062533_388946/result.json`. 앞선061708 시도는 기존 실행창 때문에 장치 접근 전에 차단됐고, 종료를 확인한 뒤 검사했다. 실제 모터 동작 중 재발 여부는 아직 확인 전이다. 새 실행을 하려면 기존 실행창을 정상 종료하고 다시 열어야 한다.
