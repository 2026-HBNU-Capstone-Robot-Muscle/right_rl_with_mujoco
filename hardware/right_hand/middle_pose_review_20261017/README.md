실기 설정 변경, 모터 구동, SAC 경로 갱신은 하지 않았다.

## 새 영상과 사용자 비교 답변

사용자는 **오른쪽이 더 비슷하지만 여전히 다르다**고 답했다.
따라서 그림 비교 요청은 완료됐으며, +51.1도 가설은 확인된 보정값이 아니다.

`KakaoTalk_20261017_010259283.mp4` 전체476프레임(30fps, 약15.87초)을
검사했다. 대표20장과 원본 해시·시간은 `phone_video/metadata.json`에 있다.
약14.17초의 측면 영상에서는 사용자가 지목한 중지 끝부분과 엄지 끝모터
하우징의 경계가 맞닿아 보인다. 접촉력이나 ID12 정지의 유일한 원인까지
영상으로 측정한 것은 아니다. 새 영상과 이전 엔코더 읽기는 동기화되지 않았다.

모델 양쪽 측면을 추가 렌더링한 `side_hypothesis_comparison.jpg`에서
뿌리만 바꾼 가설은 끝부분 기울기도 크게 바꾼다. 모델의 끝패드 긴 축과
손바닥 평면 사이 각도는 기본 약0.70도, 가설 약48.38도다. 이 숫자는
**모델 내부 수치**이며, 휴대폰 영상에서 측정한 실제 관절 각도가 아니다.
영상의 원근·카메라 자세가 등록되지 않았으므로 투영 모양만으로 이 각도나
다른 관절의 보정값을 확정하지 않는다.

전체 영상 마커 검사: ID40 검출30프레임, ID41 검출36프레임,
같은 프레임에서 두 마커 동시 검출0프레임. 결과는 `phone_video/markers_full.json`.
이는 사용한 검출기의 결과이며 물리적으로 두 마커가 한 번도 보이지 않았다는
증명은 아니다. 이번 영상으로 두 마커의 새 상대 좌표나 카메라 보정을
확정하지 않았다. 기존 웹캠 내부 파라미터도 휴대폰에 적용하지 않는다.

현재 결론: 접촉 위치에 관한 사용자의 설명과 새 영상은 일치하지만,
중지 뿌리 하나만 바꾸는 가설은 실물 자세 전체를 설명하지 못한다.
중지 네 관절의 조합과 모델/실물 대응을 더 검증해야 한다. 사진·같은 읽기·
같은 구동의 반복 요청은 없다. 실기 영점, 목표, 게인, 보호 기준은 변경하지 않았다.

## 여러 관절 비교 후 필요한 자료

`middle_multi_joint_candidates.py`에서 중지 여러 관절의118,203개 모델
조합을 검사했다. 끝패드 기울기20도 이하라는 **탐색용 가정** 아래 끝패드와
엄지 상자가 겹치지 않고2mm 이내인 표본은925개였다. 영상에서20도를
측정했다는 뜻이 아니며, 다른 손가락/받침과의 충돌도 이 검사에 포함하지
않았다. 따라서 실물 가능한 자세925개나 보정 성공으로 해석하면 안 된다.
세 가지 다른 예를 저장해 단일 접촉만으로 영점을 정할 수 없음을 확인했다.

현재 필요한 것은 새 사진과 각도를 한 기록 구간에 묶는 측정이다.
`leap_pose_pair_readonly.cmd`는 한 번의 SPACE로 앞뒤16모터 읽기 사이의
새 웹캠 사진을 저장한다. 구동이나 마커 인식 조건 없이 현재 자세를 유지한다.
자세 일치 가정과 실제 보정 오차를 구분하기 위한 자료이며, 자동으로
보정값을 설치하거나 기존 구동을 반복하지 않는다. 실행 안내는 상위 폴더의
`leap_pose_pair_readonly_README.md`에 있다.
