# xlerobot 업로드 준비 상태

대상: `https://github.com/star1209042/xlerobot.git`

- 원본 코드와 모델 및 실험 자료는 그대로 두고 별도 폴더로 복사했다. 진행 문서와 새 인계 준비 파일만 추가 및 수정했다.
- 별도 `upload_repo/`에 원본 3,519개 파일, 약 496MB와 클라우드 안내 파일을 모았다. 전체 원본 백업은 아니며 설치 환경과 대부분의 원시 영상은 제외했다.
- 현재 동작에 결합된 원본 170개 파일의 SHA256이 유지된다.
- Windows 파일 검사와 Linux MuJoCo 3.9.0 저장 모델 검사(200단계)를 통과했다. 장치는 열지 않았다. 전체 과거 환경이나 실물 성공을 검증한 것은 아니다.
- 공식 GitHub CLI v2.103.3을 `.runtime/github-cli/gh.exe`에 설치했고 공식 체크섬과 일치한다. 이 도구와 계정 정보는 업로드 폴더에 포함하지 않는다.
- 원격 최초 조회는 GitHub 인증이 없어 실패했다. 저장소 내용과 공개 여부를 확인하지 못했으므로 아직 push하지 않았다.
- 브라우저 GitHub 로그인을 요청했다. 완료 후 저장소가 의도한 비공개 저장소인지, 쓰기 권한과 기존 파일이 있는지 확인한다. 기존 파일이 있으면 별도 브랜치/하위 폴더로 보존하여 추가한다. 강제 push는 하지 않는다.
- 로컬 Git 준비 결과는 `local_git_snapshot.json`에 저장한다. 이 파일의 로컬 커밋 해시는 원격 업로드 완료를 뜻하지 않는다. push 완료 시 별도 원격 확인 기록을 저장해야 한다.

## 인증 뒤 이어갈 일

1. GitHub CLI에서 인증된 계정과 대상 저장소 메타데이터만 조회한다. 토큰 값을 출력하지 않는다.
2. 원격 기존 이력과 파일을 확인하고 필요한 경우 저장소의 AGENTS.md도 읽는다.
3. `codex/cloud-handoff-20261106` 같은 새 브랜치로 업로드한다. 기존 기본 브랜치를 강제로 덮어쓰지 않는다.
4. 원격 커밋 해시를 다시 읽어 실제 업로드를 확인한다.
5. Codex 웹에서 이 저장소와 해당 브랜치를 선택하여 클라우드 환경을 만든다. 최소 환경은 `requirements-cloud.txt`, 기본 검사는 `python -B cloud/smoke.py`다. 다른 저장소 파일을 보존하는 하위 폴더 구조로 업로드했다면 작업 디렉터리도 그 폴더로 설정한다.
6. 환경이 게시된 뒤 VS Code의 기존 대화에서 클라우드 환경을 선택해 새 요청을 보내거나, 웹의 새 클라우드 작업에 인계문을 첨부한다. 대화 맥락 전달과 로컬 기록 원문 전체의 자동 동기화는 구분한다.
