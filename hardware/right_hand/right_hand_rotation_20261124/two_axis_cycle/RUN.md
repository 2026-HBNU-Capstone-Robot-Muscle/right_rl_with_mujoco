# 오른손 가로·세로 연속 실행

실행파일: [leap_two_axis_cycle.cmd](../../leap_two_axis_cycle.cmd). 기존 가로·세로 단독 파일은 변경하지 않았다.

**G → 가로 회전 → 같은 G 약10초 유지 → 세로 회전 → 같은 G 계속 유지**를 한 제어기에서 실행한다. 중간 OFF·새 초기화·확인 SPACE는 없다. 자동으로 계속 회전을 반복하는 파일은 아니며, 가로1회와 세로1회 뒤 G에서 유지한다.

1. 기존 실행창이 유지 중이면 큐브를 받친 뒤 SPACE로 정상 종료한다.
2. 큐브를 확정 파지 자리에 준비하고 새 실행파일을 연다. 손을 뗀 뒤 SPACE 한 번으로 시작한다.
3. 손으로 큐브를 재배치하지 않고 두 회전과 복귀가 연결되는지 관찰한다. 이동 중 SPACE/Q/Esc는 중단/OFF다.
4. 마지막 G는 계속 유지한다. 큐브를 받친 뒤 SPACE로 종료/OFF한다.

1배75ms/최대2틱/450mA/기존PID와 전압·온도·추종·유지관절·진행·통신 중단 기준은 같다. 가로에서만 기존 수동 기록에 묶인 관절 범위를 쓰며, 세로와 초기 준비·마지막 유지에서는 원래 범위를 쓴다. EEPROM이나 공유 실행기 소스는 바꾸지 않는다.

연결 본체는 기존 가로5278목표와 최신 세로5549목표를 그대로 합쳤다. 세로는 불필요한 엄지 후퇴를 제거한 최신본이다. 가로 회전 끝 정착과 G 복귀 후 약10초 유지도 기존 경로 안의 목표 그대로다. 새 연결점은 양쪽 공통 G이며 첫 세로 목표 차이는 최대2틱이다. 초기 준비는 기존 세로 파일의 엄지 선행 G 준비를 사용한다.

G 근처 시작 예시는10874목표/설정상815.55초(약13분36초)다. 현재 자세에서 G 준비와 통신·추종 대기로 더 걸릴 수 있다. 이 새 연결 파일은 전체500초 제한 없이 진행하며 마지막 유지도 시간 종료가 없다. 기존 가로 단독 파일의500초 제한은 그대로다.

소프트웨어10검사와 장치 없는 실행 통과: 두 원본 목표열 완전 보존,500초를 넘긴 전체 진행,중간OFF 없음,시작OFF에서1회만ON,G경계 이상 시 세로 차단,세로 이상 시 최종유지 미판정,정상/오류/중단 때OFF·설정복구,가로 범위의 세로 적용 방지,원본변경 거부를 확인했다. 관절 목표 연결의 소프트웨어 검증이며 큐브의 실제 위치·방향·파지 하중이나 두 동작 연속 실물 성공을 인증한 결과는 아니다.

결과는 outputs/two_axis_cycle_trial_날짜_시각/result.json에 저장된다. 종료 확인 실패가 뜨면 큐브를 받친 뒤 모터 전원을 끈다.
